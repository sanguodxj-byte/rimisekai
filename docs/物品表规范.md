# 物品表规范

本规范约束项目中可进入背包、仓储、交易、配方和掉落引用的物品定义。普通物品定义保存在 `content/defs/things.json`（`ThingDef`）；装备材料保存在 `content/defs/materials.xml`（`MaterialDef`），它继承 `ThingDef`，因此材料本身也是物品。两者合起来由 `Items.All()`、`Items.Get()` 统一查询。装备运行时实例（如 `wpn_7`、`eqp_7`）不是物品定义行，见[装备表规范](装备表规范.md)。

## 文件格式与主键规则

- `things.json` 使用 UTF-8 JSON，根对象为 `{"defType":"ThingDef","defs":[...]}`；字段使用小驼峰，`defs` 中每个对象是一行。
- `materials.xml` 使用 UTF-8 XML，根节点为 `<Defs>`，每行使用 `<MaterialDef>` 元素；材料专有字段见[装备表规范](装备表规范.md)。
- `defName` 是稳定、非空的物品键；不规定必须使用英文或某一种大小写格式，因为现有表同时使用中文名和英文键。引用时必须逐字使用 `defName`，不能用 `label`、名称、序号或运行时实例 ID。
- `ThingDef` 与 `MaterialDef` 的 `defName`、`label` 均不得重复（不区分大小写）。材料只在 `materials.xml` 定义一次，不在 `things.json` 另建同名物品。
- 所有物品 `category` 必须指向 `content/defs/categories.json` 中存在的 `ThingCategoryDef.defName`。品类的 `parentCategory` 也必须引用存在的品类；根品类的父项为空字符串。

## `ThingDef` 字段

| 字段 | 要求 | 说明 |
|---|---|---|
| `defName` | 必填；非空且稳定 | 程序引用键；ThingDef 与 MaterialDef 之间不得重复 |
| `label` | 必填；非空且物品间唯一 | 玩家可见名称 |
| `description` | 必填；非空 | 物品说明；材料的说明可按装备表规范省略 |
| `category` | 必填；非空且可解析 | 所属物品分类的 `defName` |
| `stackLimit` | 必填；整数 `≥ 0` | 单堆上限；`0` 表示不限，正数为上限 |
| `marketValue` | 必填；整数 `≥ 0` | 市场基准价值，使用项目当前货币单位 |
| `isFood` | 必填；布尔值 | 是否能作为食物食用 |
| `foodTier` | 可省略，默认 `Plain` | `Plain`、`Delicate`、`Feast`、`Exquisite` 之一；非食物不依赖此值 |
| `nutrition` | 可省略，默认 `20`；整数 `≥ 0` | 食用时提供的营养/饱腹恢复点数；非食物不依赖此值 |
| `moodBonus` | 可省略，默认 `0`；整数，可正可负 | 食用后的心情修正 |
| `weapon` | 可省略；有效 `WeaponType` 或 `null` | 有值时 `IsWeapon` 为真；仅用于确为武器的物品定义 |
| `material` | 可省略，默认空字符串 | 材料标签，不是 `MaterialDef` 引用键；仅在明确需要材料属性筛选时填写 |

当前 `ThingDef` 的默认值为 `stackLimit=999`、`marketValue=1`、`isFood=false`、`foodTier=Plain`、`nutrition=20`、`moodBonus=0`、`material=""`；但普通物品表现有各行均显式提供前七项。为方便审阅与平衡，新增 `ThingDef` 应显式填写 `defName`、`label`、`description`、`category`、`stackLimit`、`marketValue` 与 `isFood`；食物应显式填写 `foodTier`、`nutrition`、`moodBonus`。`weapon` 省略等于 `null`。

当 `isFood=true` 时，`foodTier` 必须使用有效枚举值，`nutrition` 应为正整数；`moodBonus` 可为负数。非食物不因保留默认的 `foodTier` 或 `nutrition` 字段而变成食物，这由 `isFood` 决定。

## 引用规则

物品引用一律指向静态定义键：`RecipeDef.itemId`、配方成本、房间/设施成本与产出、作物种子/产物、怪物掉落等都必须能由 `Items.Get(itemId)` 找到。因此 `itemId` 可以是 `things.json` 中的 `ThingDef.defName`，也可以是 `materials.xml` 中的 `MaterialDef.defName`。技能 ID、显示文本和 `wpn_*`/`eqp_*` 实例 ID 不能用作物品定义引用。

任务 `rewards` 当前是给玩家看的文本数组，不是物品 ID 表；不得仅因其中出现物品名称，就把显示字符串当作程序引用。若未来要将任务奖励改成结构化物品引用，应先定义对应的数据模型与字段规范，再改数据。

## 示例

以下数据取自现有面包定义：

```json
{
  "defName": "bread",
  "label": "面包",
  "description": "炉火烤制出的金黄粗麦面包，表皮松脆，内里散发着质朴麦香。",
  "category": "Meal",
  "stackLimit": 999,
  "marketValue": 3,
  "isFood": true,
  "foodTier": "Plain",
  "nutrition": 30,
  "moodBonus": 0
}
```

## 修改前检查

1. JSON/XML 可解析，根结构与行类型正确，没有当前模型不支持的字段。
2. `defName`、`label` 无重复；每条物品的分类和分类父项都可解析。
3. 堆叠上限、市场价值、营养等数值符合范围；食物等级使用现有 `FoodTier` 枚举值。
4. 所有物品引用都能通过 `Items.Get()` 找到；特别确认材料引用来自 `materials.xml`，而不是重复抄进 `things.json`。
5. 确认静态定义与运行时实例没有混用：常规生成装备由材料/类型轴定义，实例 ID 只用于背包、装备栏和存档状态。
