# 怪物表规范

本规范约束项目中所有战斗怪物定义（`Rimisekai.Catalog.EnemyDef`）。当前项目没有独立的 `enemies.json`：任务怪物写在 `content/defs/quests.json` 的 `defs[].foes[]`，野外遭遇写在 `content/map_defs.json` 的 `wilds.events[].foes[]`，Roguelike 副本守卫与首领分别写在 `content/dungeon_defs.json` 的 `rules.guards[].foes[]`、`rules.bosses[].foes[]`。这些位置中的每个 `foes` 元素都是一个怪物模板；战斗开始时它会交给角色生成器掷出实战身板，而不是直接写死生命、攻击、速度等面板数值。

## 编写规则

- 文件使用 UTF-8 JSON；字段采用小驼峰写法，与现有内容一致。数组保持 JSON 数组，不用逗号分隔字符串代替。
- `id` 是程序识别单个参战条目的稳定键，不是怪物种类名：用小写 ASCII `snake_case`，并在任务、野外与副本的全部怪物行之间全局唯一。改名或换立绘不改 `id`；同一遭遇中出现多个同类单位时，每个单位仍需不同的 `id`，可共用 `name` 与 `portrait`。同一 `id` 交给生成器时会得到固定身板。
- `name` 是玩家可见名称。名称不得附加站位、序号或状态后缀；阵列位置由 `threatTier`、`column` 和 `size` 表示。
- 一条怪物行只声明单位自身数据与站位，不把遭遇几率、地点、危险等级门槛或绕行时间塞入怪物行；这些属于外围 `EncounterDef` / `WildsDef`。
- `foes` 为空表示该条遭遇不启动战斗；需要战斗的遭遇必须至少有一个单位。

## 字段约定

“必填”表示每条怪物行都必须显式提供；“可省略”表示省略时按当前 `EnemyDef` 属性初值处理。生命、攻击、防御、闪避、法力和速度不属于内容表字段，它们由 `CharacterGenerator` 根据武器、天资、属性池和经验池生成。

| 字段 | 约定 | 说明 |
|---|---|---|
| `id` | 必填；非空且全局唯一 | 小写 `snake_case`，仅用 `a-z`、`0-9`、`_`，首字符为字母 |
| `name` | 必填；非空 | 玩家可见名称；允许不同条目同名 |
| `portrait` | 必填；字符串 | 资源名（不带路径与 `.png`）；空字符串表示不使用怪物立绘/头像 |
| `weapon` | 可省略；武器枚举 | `sword`、`axe`、`spear`、`bow`、`staff`、`dagger`、`crossbow`、`unarmed`；省略时徒手 |
| `primary` | 可省略；核心属性枚举 | 主天资；省略时由生成器随机决定 |
| `secondary` | 可省略；核心属性枚举 | 副天资；省略时由生成器随机决定 |
| `corePool` | 可省略，默认 `21`；整数 `≥ 0` | 生成器在基础属性之外分配的属性点池 |
| `expPool` | 可省略，默认 `3000`；整数 `≥ 0` | 生成器分配的经验池 |
| `threatTier` | 可省略，默认 `1`；整数 `1–4` | 战场深度/威胁位置，4 为最前排，1 为最后排 |
| `column` | 可省略，默认 `1`；整数 `1–4` | 占位左端列；列号从 1 开始 |
| `size` | 可省略，默认 `1`；整数 `1–4` | 方形占位边长；精英或首领可大于 1 |
| `armour` | 可省略，默认 `0`；整数 `≥ 0` | 护甲，按实数减伤 |
| `actionPoints` | 可省略，默认 `1`；整数 `≥ 1` | 每次行动的行动点数 |
| `money` | 可省略，默认 `0`；整数 `≥ 0` | 击败该单位获得的金币 |
| `skills` | 可省略，默认 `[]` | 额外技能 Id 列表；每个 Id 必须存在于 `content/defs/skills.json`。普通攻击与防御架势为战斗内置技能，不必列入 |
| `loot` | 可省略，默认 `[]` | 击败后的物品掉落行，见下文 |
| `gear` | 可省略 | 装备掉落覆盖行（专属装备），见下文「装备掉落」；不写即全按规则表掷 |

### 掉落行

每个 `loot` 元素必须包含 `itemId`、`min`、`max`、`ratePercent`：`itemId` 必须匹配 `content/defs/things.json` 的 `ThingDef.defName` 或 `content/defs/materials.xml` 的 `MaterialDef.defName`。材料定义本身也是物品；`min`、`max` 为正整数且 `max ≥ min`；`ratePercent` 为 `0–100` 的整数。一个怪物的 `loot` 中，同一 `itemId` 只写一行；多份数量用 `min` 与 `max` 表达。

### 装备掉落

所有敌人（含野兽）都可能掉装备，「最好的装备都是掉的」。规则数值全在 `content/defs/gear_drops.json`（`GearDropDef`，唯一一行 `GearDrop_Standard`），怪物行只在需要专属掉落时写 `gear`。只在**打赢**时、只从**倒下**的敌人身上掷，每场不设件数上限；掉落的实例登记进武器/防具饰品表，按实例 Id 进主人背包，结算屏战利品条照列。

| 规则 | 现值（`gear_drops.json` 字段） |
|---|---|
| 每只倒下的敌人掉一件的概率，按 `threatTier` | 1→8%、2→20%、3→60%、4→100%（`threats[]`） |
| 第二件 | `threatTier ≥ 4` 再掷 40%（`extraDropThreat`、`extraDropPercent`） |
| 委托首领保底 | 委托地城的正主、首领战委托的首领（首波里威胁等级最高者）至少 1 件（`questBossMinDrops`） |
| 种类 | 武器 40 / 防具 45 / 饰品 15（`weaponWeight`…）；有 `weapon` 的敌人掉武器用自己的武器类型，徒手的随机；防具在 6 个甲位均匀抽；饰品类型按 `AccessoryDef.weight`，饰位戒指/项链各 1（`accessorySlots`） |
| 材质，按战斗发生地危险等级（野外离领地远近 1–4，地城 `run.Tier`，战斗委托按难度） | T1 武器 木材/青铜/珊瑚、防具饰品 布/皮；T2 青铜/珊瑚/铁、皮/铁；T3 铁/钢/秘银；T4 钢/秘银/精金（`tiers[].weapon/armor`，窗口内等权） |
| 首领材质升档 | `threatTier ≥ 3`（`bossThreat`）的敌人 30% 沿材料表（该种类能用的材料按 `tier` 排）再升一档，以太封顶（`bossMaterialUpgradePercent`） |
| 品质 | 小兵（威胁 1–2）粗劣30 寻常45 精致18 史诗6 传说1；首领（≥3）寻常15 精致35 史诗32 传说18（`minion/boss.quality`）；独特不随机 |
| 附魔 | T1 15% / T2 30% / T3 50% / T4 70%（`tiers[].enchantPercent`），首领 +20（`bossEnchantBonus`），中了按附魔表权重抽 |
| 祝福 | 小兵 5%、首领 25%（`blessedPercent`） |
| 强化 | 小兵 15% 概率 +1..2；首领 50% 概率 +1..5（`enhancePercent/Min/Max`；锻造上限 +3，掉落可更高） |

`gear` 覆盖行把这只怪的**第一件**定死成指定种类，掉率用 `ratePercent` 代替威胁等级掉率；材质、品质只给下限，掷出来更好的照留。威胁 4 的第二件与附魔、祝福、强化仍按规则表掷。

| 字段 | 约定 | 说明 |
|---|---|---|
| `kind` | 必填；`weapon` / `armor` / `accessory` | 掉哪类 |
| `weaponType` | 可省略；武器枚举（不含 `unarmed`） | 只对 `weapon`；省略用怪物自己的 `weapon`，徒手的随机 |
| `slot` | 可省略；`head` `torso` `legs` `hands` `feet` `offHand`（防具）或 `ring1` `neck`（饰品） | 省略随机 |
| `minMaterial` | 可省略；`materials.xml` 的 `defName`，须能做该种类 | 材质下限；掷出的档次低于它就换成它 |
| `minQuality` | 可省略；`crude` `common` `fine` `epic` `legendary` | 品质下限；不得写 `unique` |
| `ratePercent` | 可省略，默认 `100`；整数 `0–100` | 这件的掉率 |

示例（骸骨王 `dg_boss_lich`：必掉钢或更好材质的剑）：

```json
"gear": { "kind": "weapon", "weaponType": "sword", "minMaterial": "钢", "ratePercent": 100 }
```

### 布阵边界

战场为 4 列 × 4 层。`size` 单位从 `column` 向右、从 `threatTier` 所在层向纵深延展，因此每条怪物行必须同时满足：

- `column + size - 1 ≤ 4`
- `size ≤ threatTier`

违反边界会使占位超出 4×4 战场，不能依赖运行时裁切或钳位补救。`threatTier` 越高越靠前；`column` 越小越靠左。

## 立绘与头像

非空 `portrait` 是资源文件名主干，运行时分别从 `assets/portraits/monster/{portrait}.png` 读取战斗立绘、从 `assets/avatars/monster/{portrait}.png` 读取头像裁切。使用同一主干的资源应对应同一种怪物；缺少某一种文件会导致对应画面没有该图。项目 `.gitignore` 将 `assets/` 排除在 Git 版本控制之外，表格只能引用资源名，不能把本地绝对路径写入 JSON。没有可用资源时将 `portrait` 设为空字符串。

## 规范示例

以下字段值取自当前任务表中的 `rat_a` 条目，展示生成器使用的模板输入。

```json
{
  "id": "rat_a",
  "portrait": "monster_giant_rat",
  "name": "大鼠",
  "primary": "speed",
  "secondary": "dexterity",
  "corePool": 4,
  "expPool": 300,
  "threatTier": 1,
  "column": 1,
  "money": 6
}
```

## 修改前检查

1. JSON 能正常解析，字段名与本规范一致，没有拼写错误或未定义字段。
2. 三个位置的怪物数据中的 `id` 无重复，必填字段存在且类型正确；可省略字段按 `EnemyDef` 默认值处理。
3. 生成器字段和站位数值符合边界；大体型单位同时满足两条布阵边界。
4. `skills` 与 `loot.itemId` 都能分别在技能表、物品表中找到对应 `defName`；`gear.minMaterial` 能在材料表中找到且能做该种类装备。
5. 非空 `portrait` 的立绘与头像资源名一致；若无资源，使用空字符串。
