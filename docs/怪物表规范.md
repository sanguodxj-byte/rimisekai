# 怪物表规范

本规范约束项目中所有战斗怪物定义（`Rimisekai.Catalog.EnemyDef`）。当前项目没有独立的 `enemies.json`：任务怪物写在 `content/defs/quests.json` 的 `defs[].foes[]`，野外与地城怪物写在 `content/map_defs.json` 的 `wilds.events[].foes[]`、`dungeon.guards[].foes[]` 和 `dungeon.bosses[].foes[]`。这些位置中的每个 `foes` 元素都是一个实际参战单位；本规范统一其数据形状，不新增另一套主表或引用格式。

## 编写规则

- 文件使用 UTF-8 JSON；字段采用小驼峰写法，与现有内容一致。数组保持 JSON 数组，不用逗号分隔字符串代替。
- `id` 是程序识别单个参战条目的稳定键，不是怪物种类名：用小写 ASCII `snake_case`，并在两个文件的全部怪物行之间全局唯一。改名或换立绘不改 `id`；同一遭遇中出现多个同类单位时，每个单位仍需不同的 `id`，可共用 `name` 与 `portrait`。
- `name` 是玩家可见名称。名称不得附加站位、序号或状态后缀；阵列位置由 `threatTier`、`column` 和 `size` 表示。
- 一条怪物行只声明单位自身数据与站位，不把遭遇几率、地点、危险等级门槛或绕行时间塞入怪物行；这些属于外围 `EncounterDef` / `WildsDef`。
- `foes` 为空表示该条遭遇不启动战斗；需要战斗的遭遇必须至少有一个单位。

## 字段约定

“必填”表示每条怪物行都必须显式提供；“可省略”表示省略时按当前 `EnemyDef` 属性初值处理。

| 字段 | 约定 | 说明 |
|---|---|---|
| `id` | 必填；非空且全局唯一 | 小写 `snake_case`，仅用 `a-z`、`0-9`、`_`，首字符为字母 |
| `name` | 必填；非空 | 玩家可见名称；允许不同条目同名 |
| `portrait` | 必填；字符串 | 资源名（不带路径与 `.png`）；空字符串表示不使用怪物立绘/头像 |
| `maxHp` | 必填；整数 `> 0` | 最大生命值 |
| `attack` | 必填；整数 `≥ 0` | 攻击数值 |
| `speed` | 必填；整数 `> 0` | 战斗行动速度 |
| `threatTier` | 必填；整数 `1–4` | 战场深度/威胁位置，4 为最前排，1 为最后排 |
| `column` | 必填；整数 `1–4` | 占位左端列；列号从 1 开始 |
| `size` | 可省略，默认 `1`；整数 `1–4` | 方形占位边长；精英或首领可大于 1 |
| `defence` | 可省略，默认 `0`；整数 `≥ 0` | 防御数值 |
| `dodge` | 可省略，默认 `0`；整数 `≥ 0` | 闪避数值 |
| `spellPower` | 可省略，默认 `0`；整数 `≥ 0` | 法术强度 |
| `armour` | 可省略，默认 `0`；整数 `≥ 0` | 护甲，按实数减伤 |
| `actionPoints` | 可省略，默认 `1`；整数 `≥ 1` | 每次行动的行动点数 |
| `money` | 必填；整数 `≥ 0` | 击败该单位获得的金币 |
| `skills` | 可省略，默认 `[]` | 额外技能 Id 列表；每个 Id 必须存在于 `content/defs/skills.json`。普通攻击与防御架势为战斗内置技能，不必列入 |
| `loot` | 可省略，默认 `[]` | 击败后的物品掉落行，见下文 |

### 掉落行

每个 `loot` 元素必须包含 `itemId`、`min`、`max`、`ratePercent`：`itemId` 必须匹配 `content/defs/things.json` 中某个 `defName`；`min`、`max` 为正整数且 `max ≥ min`；`ratePercent` 为 `0–100` 的整数。一个怪物的 `loot` 中，同一 `itemId` 只写一行；多份数量用 `min` 与 `max` 表达。

### 布阵边界

战场为 4 列 × 4 层。`size` 单位从 `column` 向右、从 `threatTier` 所在层向纵深延展，因此每条怪物行必须同时满足：

- `column + size - 1 ≤ 4`
- `size ≤ threatTier`

违反边界会使占位超出 4×4 战场，不能依赖运行时裁切或钳位补救。`threatTier` 越高越靠前；`column` 越小越靠左。

## 立绘与头像

非空 `portrait` 是资源文件名主干，运行时分别从 `assets/portraits/monster/{portrait}.png` 读取战斗立绘、从 `assets/avatars/monster/{portrait}.png` 读取头像裁切。使用同一主干的资源应对应同一种怪物；缺少某一种文件会导致对应画面没有该图。项目 `.gitignore` 将 `assets/` 排除在 Git 版本控制之外，表格只能引用资源名，不能把本地绝对路径写入 JSON。没有可用资源时将 `portrait` 设为空字符串。

## 规范示例

以下字段值取自现有 `wolf_scout` 条目；为展示完整结构，省略时等于默认值的字段也显式写出。

```json
{
  "id": "wolf_scout",
  "portrait": "monster_dire_wolf",
  "name": "野狼",
  "maxHp": 30,
  "attack": 3,
  "defence": 0,
  "dodge": 0,
  "spellPower": 0,
  "speed": 10,
  "threatTier": 1,
  "column": 1,
  "size": 1,
  "actionPoints": 1,
  "armour": 0,
  "money": 10,
  "skills": [],
  "loot": []
}
```

## 修改前检查

1. JSON 能正常解析，字段名与本规范一致，没有拼写错误或未定义字段。
2. 两处怪物数据中的 `id` 无重复，所有必填字段存在且类型正确。
3. 数值符合字段边界；大体型单位同时满足两条布阵边界。
4. `skills` 与 `loot.itemId` 都能分别在技能表、物品表中找到对应 `defName`。
5. 非空 `portrait` 的立绘与头像资源名一致；若无资源，使用空字符串。
