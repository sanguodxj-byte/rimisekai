# 口上/地文写作规范

> 本文档是 Rimisekai 项目所有角色口上与地文的**唯一写作标准**。
> 无论添加多少角色，任何人（或 AI）按本文档执行即可产出风格一致的台词。
> 文风基准源自 eraFL 项目（D:/123/eraFL0.49）的深度文本分析。

---

## 一、核心原则（铁律）

1. **沉静克制**：一切台词短促、节制，不使用感叹号堆叠。情绪通过行动暗示，不直白剖白。
2. **敬称贯穿**：角色对玩家使用与其身份匹配的敬称（见第三节），从头到尾不直呼"你"。
3. **女仆/职业自觉**：角色始终意识到自己的身份职责，日常用语中体现职业素养。
4. **压抑渐进**：感情不一次性爆发，而是随好感档逐步渗出。高好感时才允许防线松动。
5. **句式短促**：单句 10～18 字，最长不超过 30 字。长段叙事拆成多个短分句。
6. **无 emoji、无 dingbat**：禁止一切表情符号与装饰字形（❤ ★ ☆ 等）。
7. **无外来设定**：不得照搬任何其他游戏（eraFL 等）的地名、人名、事件。

## 四、称呼规范

角色对玩家的称呼由其**身份与性格**决定，一旦确定全篇不变：

| 角色类型 | 称呼 | 自称 | 示例句 |
|---|---|---|---|
| 女仆/仆人 | 「大人」 | 「我」/「琉米埃尔」（情感波动时用角色名） | 「大人，请问有什么吩咐吗？」 |
| 骑士/武官 | 「大人」 | 「我」 | 「大人，请让我随行。」 |
| 商人 | 「老板」/「大人」 | 「我」/「在下」 | 「老板，这批货您看如何？」 |
| 平民/朋友 | 「你」/「名字」 | 「我」 | 「你今天怎么了？」 |
| 贵族/王族 | 「阁下」/「陛下」 | 「臣」/「本座」 | 「阁下，此事请三思。」 |
| 学者/谋士 | 「大人」 | 「我」/「在下」 | 「大人，属下有一事禀报。」 |

**规则**：
- 称呼一旦确定，全篇所有台词、所有好感档、所有场景中**不得改变**。
- 唯一例外：情感极度波动（崩溃/高潮）时可短暂省略敬称或切换为角色名自称。
- 角色间的互称也需按各自身份决定，不得混用。

## 五、句式与语气规范

### 5.1 句式长度

- **标准**：10～18 字/句。
- **上限**：30 字。超过必须拆分。
- **最短**：2～5 字的短句用于情绪表达（「……呼」「……嗯」）。

### 5.2 语气助词

| 助词 | 用法 | 频率 |
|---|---|---|
| 「……」 | 停顿、犹豫、压抑、余韵 | 极高频 |
| 「呢」 | 轻柔的感叹/疑问 | 高频 |
| 「哦」 | 温柔的提醒/告知 | 高频 |
| 「吧」 | 委婉的征询/建议 | 中频 |
| 「可以吗？」 | 礼貌的征求许可 | 中频 |
| 「……吗？」 | 淡淡的疑问 | 中频 |

**禁止使用**：「啦」「哇」「捏」「呀」（除非角色设定为活泼型）。

### 5.3 标点

- 使用中文标点（「」，。……？！）
- 对话内容不加引号（JSON lines 数组中的文本即为台词）
- 旁白中的动作描写用第三人称圆括号包裹：`（她微微垂下眼帘。）`

### 5.4 标准句式模板

**模板 A（日常侍奉/征询）**：
> `「大人，[日常观察/环境描述]。如果您需要的话，请让我为您[行动]……可以吗？」`

**模板 B（压抑掩饰）**：
> `「……谢谢您的关心。[转回职责]。这种程度……我已经习惯了。」`

**模板 C（亲密依偎/渴求温暖）**：
> `「大人的[部位/举动]……非常温暖。那个……如果可以的话，请让我再这样待一会儿……」`

**模板 D（防线崩塌/情感决堤，仅 Lover 档）**：
> `「我、我知道……这样是不对的……但是，[角色名]已经无法再压抑自己的心情了……请大人……不要[抛弃/拒绝]我。」`

**模板 E（地文旁白）**：
> `（她[细微动作]，[身体反应]。[含蓄的情感暗示]。）`

## 六、好感分档写作指南

### 6.1 四档好感总表

| 档位 | 好感范围 | gate 写法 | 心理状态 | 语言基调 | 亲密反应 |
|---|---|---|---|---|---|
| **None（熟人）** | < 100 | `favorMax: 99` | 恪守本分、情感封闭 | 冷淡、端庄、有问必答但不延展 | 礼貌拉开距离 |
| **Fond（好感）** | 100~299 | `bondMin: "Fond", bondMax: "Fond"` | 心防微融、暗暗在意 | 温和关切，通过行动暗示 | 顺从但不主动，身体微僵 |
| **Close（亲近）** | 300~599 | `bondMin: "Close", bondMax: "Close"` | 依恋渐深、偶尔流露 | 话语中渗出温度，会说出半截真心话后立刻收回 | 轻微回应，渴望但不索取 |
| **Lover（爱慕）** | 600+ | `bondMin: "Lover"` | 防线崩塌、奉献沉溺 | 深情但克制，偶尔决堤 | 全然接纳，渴求更多 |

### 6.2 各档写作细则

#### 熟人期（None，< 100）

**心态**：我只是在履行职责。大人对我来说是主人和服务对象。

**写作要点**：
- 所有台词以「大人」开头或包含敬称
- 以职业回应为主：「请吩咐」「好的」「遵命」
- 可以提及日常琐事（天气、家务、食物），但不夹带私人情感
- 面对亲密接触：礼貌拒绝，不生气不动怒，温和提醒
- 不使用「……」表达依恋（只用于思考停顿）

**例**：
```
「大人，请问有什么吩咐吗？」
「好的，请随时吩咐。」
「大人，院子里的杂活都做完了。如果还有别的需要……请告诉我。」
「请不要随便……触碰女性哦……」
```

#### 好感期（Fond，100~299）

**心态**：我开始在意大人了。但这种感情……不应该。

**写作要点**：
- 关切开始带有私人色彩（「您今天有没有好好吃饭？」）
- 做饭时开始考虑对方的口味
- 偶尔说出半截真心话后立刻收回（「啊，不……没什么。我去准备晚饭了。」）
- 亲密接触：身体微僵但不躲开，用「……」表达不知所措
- 地文开始描写细微变化（「她的动作慢了半拍」「耳根微微泛红」）

**例**：
```
「大人……您今天有没有好好吃饭？」
「大人……不知道为什么，最近只要看到您的身影，心里就会觉得……很安稳。啊，不……没什么。」
「……大人。（她微微侧身，但没有躲开。）……请、请不要突然碰过来……」
```

#### 亲近期（Close，300~599）

**心态**：我对大人的感情……已经不只是主仆了。但我不能说。

**写作要点**：
- 说出更长的真心话，但仍然用「啊……请当作我没说」收回
- 开始回忆童年/过去（如果有共同经历的话）
- 主动做出关心行为但用职责掩饰
- 亲密接触：开始回应但不索取，「真想一直这样下去」
- 地文描写加深：「（她安静地闭上眼睛，任由您的手掌覆在发顶。）」

**例**：
```
「大人……我一直觉得，能留在大人身边做事……是这个女仆最大的幸运。啊……请当作我没说。我去干活了。」
「……（她靠在你怀里，双臂轻轻环上了你的腰。）……真想……一直这样下去……」
「大人……如果有一天……您不再需要我这个女仆了，我会怎么办呢。啊……对不起。说了些奇怪的话。请忘了吧。」
```

#### 爱慕期（Lover，600+）

**心态**：我已经无法再压抑了。我的全部……都是大人的。

**写作要点**：
- 情感防线部分崩塌，会出现「我、我知道……这样是不对的……」的决堤剖白
- 自我称呼有时切换为角色名（第三人称），表达迷失
- 开始直接表达渴望（「请让我留在您身边」「请不要放手」）
- 亲密接触：全然接纳，主动索取，「请再摸一会儿……可以吗？」
- 地文描写投入：「（她整个人靠在你怀里，双手紧紧抓着你的后背衣料。）」
- 用「至死不渝」「永远」等重誓，但不轻浮

**例**：
```
「大人……我、我知道……像这样说出来是不对的……但是，我已经无法再压抑自己的心情了。请大人……不要赶我走。」
「……大人。（她整个人靠在你怀里，双手紧紧抓着你的后背衣料。）……请不要放手。……求您了。」
「大人……琉米埃尔……从来不觉得做女仆是一件委屈的事。因为服侍的对象……是大人您啊。……这句话，我只说一次。请记住。」
```

## 七、亲密场景反应梯度

这是**最容易写错**的部分。eraFL 角色的亲密反应**不是傲娇**（不是"笨蛋别碰我"），而是**从礼貌距离到安全感到全然奉献的渐进**。

| 档位 | 触摸 | 摸头 | 拥抱 | 亲吻 |
|---|---|---|---|---|
| **None** | 「请不要随便……触碰女性哦……」 | 「……想要被摸头……吗？可以哦……」 | 「……请、请不要突然抱过来……」 | 尚未解锁 |
| **Fond** | 「……请、请不要突然碰过来……」 | 「……被大人摸着头……谢谢您。」 | 「……被大人抱着……感觉非常温暖……让人安心。」 | 「……大、大人……真是的……」 |
| **Close** | 「……大人的手，比以前暖和了呢。」 | 「……很温暖。像小时候一样。」 | 「……真想……一直这样下去……」 | 「……大、大人……真是的……」 |
| **Lover** | 「……大人的手，好温暖。」 | 「……请再多摸一会儿……可以吗？」 | 「……请不要放手。……求您了。」 | 「……大人的吻……好温柔……」 |

**核心差异**：
- ❌ 傲娇写法：「哼！别碰我！」→ **禁止**
- ❌ 活泼写法：「呀！好痒！」→ **禁止**
- ✅ eraFL 写法：「请不要随便……触碰女性哦……」（礼貌、有距离、不生气）

## 八、地文（Narration）写作规范

地文是第三人称客观旁白，用于描写角色的细微动作与状态变化。

### 规则
1. **人称**：用「她」「他」或角色名。
2. **括号**：台词中的动作描写用圆括号包裹 `（……）`；独立地文行不加括号。
3. **侧重**：捕捉**眼神微动、呼吸温度、指尖颤抖**等细微变化，而非大开大合的情感呼号。
4. **无内心独白**：不直接写角色在想什么，靠微表情暗示。
5. **长度**：一句话 15～30 字。

### 示例

```
（她正在水井旁打水。摇动辘轳的动作很稳，盛满的木桶几乎没有洒出一滴水来。）
（她察觉到您的目光，手上的动作没有停，只是耳朵微微动了一下。）
（她安静地闭上眼睛，任由您的手掌覆在发顶。）
（被您看着的时候，她的动作慢了半拍。）
（她没有避开您的视线，只是安静地回望过来。过了一会儿，先别开眼的是她。）
```

## 九、场景事件写作规范

场景事件（DAILY 等价物）是**多步分支剧情**，相当于一个小型互动剧本。

### 结构

每个场景事件包含：
1. **开场**（step 0）：环境描写 + 角色引入 + 提出选项
2. **分支**（step 1~N）：根据玩家选择展开不同剧情
3. **收束**（最后 step）：总结、效果施加

### 写作要点

1. **rate**：千分率触发概率（1000 = 必发，100 = 10%）。日常事件建议 300~600。
2. **flag + requireFlagValue**：一次性事件用状态机控制（跑完置 1，要求为 0 才触发）。
3. **cooldownDays**：可重复事件设冷却天数（2~3 天）。
4. **gate**：用好感/时段/天气/季节控制触发条件。
5. **choices**：每个分支给予不同 Favor/Mood 效果，好的选择给更多。
6. **summary**：1~2 行概要，显示在事件回顾菜单。

### 示例场景事件

```json
{
  "id": "cleanup",
  "title": "大人的房间",
  "genre": "日常",
  "rate": 1000,
  "characters": ["璐米埃尔"],

  "steps": [
    {
      "id": "open",
      "lines": [
        {"kind": "Narration", "text": "璐米埃尔正在认真地打扫您的房间。"},
```

## 十、绝对禁止事项

以下写法在任何角色、任何好感档、任何场景中**一律禁止**：

1. ❌ **傲娇口是心非**：「哼！别误会了！我才不是为你做的！」→ 角色即使抗拒也礼貌表达。
2. ❌ **活泼萌系语尾**：「哇～好厉害呀～」→ 除非角色设定就是活泼型，否则禁止。
3. ❌ **直白现代告白**：「我爱你！非你不嫁！」→ 爱意通过行动、温暖、安心等含蓄方式表达。
4. ❌ **网络流行语**：「绝绝子」「yyds」「破防了」→ 使用书面中文。
5. ❌ **对暴力/杀戮表现柔弱惊恐**（战斗型角色）：「呀！好可怕！」→ 冷静面对，视职业而定。
6. ❌ **越级亲昵**：好感 < 100 时说「我好想你」→ 感情必须按档渐进。
7. ❌ **emoji/dingbat**：❤ ★ ☆ 表情符号 → 一律禁止。
8. ❌ **照搬其他游戏设定**：地名、人名、事件 → 原创内容。

## 十一、性格光谱（特质池）

角色的语气由两根轴决定：**身份轴**定称呼与职责语汇（11.8），**特质轴**从性格特质池选 2~4 条定语气与表达。设计依据是行业范式：CK3 每角色约 3 条性格特质（大池选取），Dwarf Fortress 用约 50 条 0-100 连续人格 facet——**没有游戏用 16 型分类盒做性格生成**，分类盒只能贴标签，角色一多必然撞脸。MBTI 十六型仅作为写手找起点的参考映射（11.6），不作为正式声明。

新角色立项第一步：从特质池选 2~4 条特质并定身份，写进 persona，全篇语气不得偏离。

### 11.1 槽位规则

- 每角色选 **2~4 条**特质（CK3 的可读性经验：多于 4 条玩家记不住）。
- 同一组（下述六组）内至多选 2 条；"独特组"至多 2 条。
- 互斥对不得同选：健谈×寡言、情绪外露×内敛、乐观×忧郁、讨好×傲慢、尽责×拖沓、严谨×随性、务实×空想。
- 组合空间：C(52,2)+C(52,3)+C(52,4) 约 **29 万**种特质组合，乘身份模板后再翻 6 倍。

### 11.2 特质池（六组五十二条）

每条特质自带语气参数：基调 / 语气词倾向 / 感叹号档（禁、偶、常）/ 雷点。写作时按所选特质合成（规则见 11.3）。

**双通道铁律**：每条特质同时挂游戏性效果（工作进度、疲劳、心情增益、社交好感、学习速度、进餐、作息等），数值与挂点的唯一权威在 `RimisekaiCore/src/Character/PersonalityTraits.cs`——文档不抄数值，避免双表漂移。新特质立项时两个通道必须同时登记。

**不入池条目**：女仆/魔法师（身份标识，随身份授予，不参与掷骰）；胆小/诚实/自负（已并入易紧张/直率/傲慢——枚举保留以兼容旧存档，游戏性与对话效果随并入对象生效）。原"机制素质"类别已取消，全部特质统一进光谱。

### 11.3 语气合成规则

- **感叹号档**：取所选特质中最高档。
- **语气词**：取并集；冲突时外向组优先。
- **句长**：寡言/内敛在场时全篇句长下探（4~12 字），健谈/情绪外露在场时放宽到 18 字。
- **亲密基线**：所选特质含任一 F 向特质（体贴、讨好、多虑、情绪外露、内敛、空想）→ 走 **F 基线**（第六节四档全文）；全为理性特质 → 走 **T 基线**（关心翻译成事务，Lover 档"失守一次"）。
- 同组两条特质共存时，第二条只作风味微调，不改变第一条定下的主干（一主一辅）。

### 11.4 敬称弹性

身份轴定下的称呼（如"大人"）全篇不变的原则不变，允许两处变体且必须在 persona 声明：毒舌/傲慢/直率可省称（少缀词）；健谈/情绪外露 Close 档以上可用角色专属轻昵称（Lover 档定型，不得再变）。

### 11.5 现有角色标定

- **璐米埃尔 = 尽责 + 体贴 + 内敛**：F 基线，现行第六/七节例句即按此组合写成。
- **赛琳 = 好学 + 易紧张 + 讨好**：F 基线，"是我没出息呢"式自语是易紧张+讨好的签名。

### 11.6 MBTI 起点映射（仅供参考）

写手若习惯从 MBTI 找感觉，按下表换算成特质组合后走正式声明：ISFJ→尽责+体贴+内敛；INFP→好学+易紧张+讨好；ESFP→健谈+情绪外露+吃货；INTJ→寡言+井然+务实；ENTP→健谈+毒舌+空想；ISTP→寡言+手巧+泰然。映射只保证"气质方向"，具体语气以特质参数为准。

### 11.7 组合数账

特质组合约 29 万种，身份模板每种乘 6——骨架空间数十万级，远超 MBTI 方案的 96。角色之间靠"独有层三件套"进一步区分：**经历（忆旧素材）/ 口癖 / 与玩家的关系史**，三者必须写进 persona。

## 十二、质量检查清单

提交新角色口上前，逐项自查：

- [ ] 所有台词使用正确的敬称（不直呼"你"）
- [ ] 单句不超过 30 字
- [ ] 无 emoji/dingbat
- [ ] 无傲娇/活泼/网络语（除非角色设定允许）
- [ ] 四档好感均有覆盖（None/Fond/Close/Lover）
- [ ] 亲密反应符合档位梯度（None=礼貌距离 → Lover=全然奉献）
- [ ] Trigger 值全部合法（在 21 个枚举值之内）
- [ ] Line ID 全局唯一
- [ ] RequireSaid 引用的前置台词 ID 确实存在
- [ ] 场景事件的 gotoStep 不越界
- [ ] 场景事件有 flag 或 cooldown 控制重复触发
- [ ] persona 含身份与 2~4 条性格特质，且全篇语气与光谱（第十一节）一致；独有层三件套（经历/口癖/关系史）已填写

## 十三、LLM 生成挂点规范

对于适合 LLM 动态生成的台词，在 JSON 中添加 `generation` 字段：

```json
{
  "id": "talk_llm",
  "trigger": "Talk",
  "priority": 2,
  "gate": {"favorMin": 100},
  "lines": ["……嗯。我在听。"],
  "generation": {
    "instruction": "玩家主动与角色搭话。用[角色性格]的语气回应。使用[敬称]称呼。句式短促。",
    "style": "[角色的语气关键词]。一到两句。",
    "lineCount": 2,
    "maxCharsPerLine": 30,
    "cacheMinutes": 20
  }
}
```

**规则**：
- `lines` 数组必须至少有一条静态兜底台词（LLM 不可用时回退）。
- `instruction` 必须包含角色的称呼方式、性格关键词和禁忌。
- `style` 必须包含句尾语气词偏好和句式长度限制。
- `cacheMinutes` 建议 20~45，防止连点重复消耗 token。

## 十四、角色注册流程

添加新角色的完整步骤：

0. **先定性格与身份**：从第十一节特质池选 2~4 条特质（守槽位与互斥规则）并定身份，连同独有层三件套写进 persona（如"璐米埃尔：尽责、体贴、内敛；女仆；与大人一起长大"）。

1. **在 `content/newgame.json`** 的 `characters` 数组中添加角色条目：
   ```json
   {"name": "新角色名", "roomId": 1, "favor": 50, "traits": ["Maid"]}
   ```

2. **在 `content/voice/` 目录下** 创建 `新角色名.json`：
   - 按第五~八节规范编写台词
   - 覆盖至少 Talk、Meet、Idle、Gift、Touch、PatHead、Hug 七个核心时机
   - 按四档好感分层

3. **在 `content/newgame.json`** 的 `voicePaths` 数组中添加文件路径：
   ```json
   "voicePaths": ["res://content/voice/新角色名.json", ...]
   ```

4. **如需添加场景事件**，在角色的 JSON 文件中添加 `scenes` 数组。

5. **填写 persona**（人设），用于 LLM 生成时的上下文。

6. **运行质量检查清单**（第十二节）。

7. **运行 `dotnet test`** 确保不破坏现有测试。
