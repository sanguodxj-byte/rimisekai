# 装备表规范

本规范约束项目中的装备基表。装备定义不是逐件装备清单：`content/defs/equipment.xml` 保存防具槽位、武器类型、饰品类型与附魔四张轴表；`content/defs/materials.xml` 是装备和物品共用的唯一材料表。武器按“可制武器材料 × 武器类型”生成，防具按“可制防具材料 × 槽位”生成，饰品按“可制防具材料 × 饰品类型”生成。品质、强化、祝福、附魔等具体结果属于运行时装备实例，不在 XML 中逐件登记。

## 文件与通用规则

- 使用 UTF-8 XML；根节点为 `<Defs>`，每个子元素的标签名就是定义类型（如 `<WeaponTypeDef>`），每个元素是一行定义。
- 子字段使用现有小驼峰标签名（如 `<defName>`、`<basePanel>`）；枚举值必须使用代码中的枚举成员拼写，区分大小写。
- `defName` 是稳定键；同一类型表内不得重复，改显示名或描述时不改键。`label` 是玩家可见名称，同一类型表内不得重复。跨表引用写 `defName`，不写行号、显示名或组合出来的装备名称。
- `Def` 基类字段为 `defName`、`label`、`description`。`defName` 与 `label` 必须非空；`description` 可省略，省略后为空字符串。空描述只适用于没有独立说明价值的轴定义。
- 不要新增“铁剑”“钢帽”等每种组合的静态行，也不要把 `wpn_*`、`eqp_*` 运行时实例 ID 写入定义表。

## `equipment.xml` 四张轴表

### 防具槽位 `ArmorSlotDef`

| 字段 | 要求 | 说明 |
|---|---|---|
| `defName` | 必填；`Head`、`Torso`、`Legs`、`Hands`、`Feet`、`OffHand` 之一 | 必须与防具 `EquipSlot` 对应；`OffHand` 是盾（木材这类能做兵器的材料也能做盾）；主手与饰品槽不属于防具槽位表 |
| `label` | 必填；非空 | 该槽位的短显示名 |
| `baseDefence` | 必填；整数 `≥ 0` | 防具槽位基准防御 |
| `noun` | 必填；非空 | 拼装备名用的物品名词，如“帽”“甲”“腿”“手”“靴”；不是装备栏的 UI 名称 |
| `description` | 可省略 | 继承 `Def` 的空字符串默认值 |

槽位名词是装备名称的一部分，修改前要检查生成名称是否仍自然，例如“铁甲”，而不是“铁上装”。

### 武器类型 `WeaponTypeDef`

| 字段 | 要求 | 说明 |
|---|---|---|
| `defName`、`label` | 必填；非空 | 稳定键与玩家可见类型名 |
| `type` | 必填；有效且不重复的 `WeaponType` | 代码枚举为 `Sword`、`Axe`、`Spear`、`Bow`、`Staff`、`Dagger`、`Crossbow`、`Unarmed`；只有需要由锻炉生成的类型才加入本表 |
| `style` | 必填；有效的 `StyleType` | `OneHand`、`TwoHand`、`DualWield`、`Ranged`、`Spell`、`Shield`、`Unarmed` 之一 |
| `core` | 必填；有效的 `CoreStat` | `Constitution`、`Dexterity`、`Intellect`、`Charm`、`Perception`、`Strength`、`Speed` 之一 |
| `basePanel` | 必填；整数 `≥ 0` | 武器类型面板基值；材料加成后再按品质等规则计算 |
| `baseValue` | 必填；整数 `> 0` | 该类型的基础价值，随后按材料与品质倍率计算 |
| `description` | 可省略 | 类型说明 |

同一个 `type` 只能有一行，否则运行时按类型查找基表会产生歧义。`defName` 通常与 `type` 同名，便于维护，但程序引用武器类型时以字段 `type` 的枚举值为准。

### 饰品类型 `AccessoryDef`

| 字段 | 要求 | 说明 |
|---|---|---|
| `defName`、`label` | 必填；非空 | 稳定键与显示名 |
| `core` | 必填；有效的 `CoreStat` | 饰品所加成的属性 |
| `baseBonus` | 必填；整数 `> 0` | 饰品基础加成 |
| `weight` | 可省略，默认 `10`；整数 `≥ 0` | 随机抽取相对权重；`0` 表示不参与随机生成，不是百分比 |
| `description` | 可省略 | 类型说明 |

饰品名称由祝福、附魔、材料与戒指/项链名词组成；属性类型放在详情中，不塞进名称。

### 附魔 `EnchantDef`

| 字段 | 要求 | 说明 |
|---|---|---|
| `defName`、`label` | 必填；非空 | 稳定键与显示名 |
| `prefix` | 有效随机附魔必填；非空 | 拼入武器、防具或饰品名称的前缀 |
| `core` | 可省略 | `CoreStat` 成员；没有属性归属时省略 |
| `coreBonus` | 可省略，默认 `0`；整数 `≥ 0` | 附魔数值加成字段；各类实例按当前计算规则使用 |
| `effect` | 可省略 | 详情中的说明文字，默认空字符串 |
| `weight` | 可省略，默认 `10`；整数 `≥ 0` | 随机抽取相对权重；`0` 表示不进入随机池 |
| `description` | 可省略 | 定义说明 |

权重是相对概率权重，池内概率由该行权重除以所有正权重总和得出；不是 `0–100` 百分比。若 `weight > 0`，必须提供非空 `prefix`，否则会抽到没有名称标记的附魔。

## 共享材料表 `materials.xml`

每个 `<MaterialDef>` 同时是一个物品定义（继承 `ThingDef`），也是装备生成的材料轴；材料只能在 `materials.xml` 定义一次，不得再在 `things.json` 复制同一个材料。通用物品字段及 `defName`、分类、堆叠、价值规则见[物品表规范](物品表规范.md)。

| 材料字段 | 要求 | 说明 |
|---|---|---|
| `tier` | 必填；整数 `≥ 0` | 材料强弱顺序，数值越大越靠后/越好；同一材料序列使用不同 tier，避免排序不确定 |
| `weaponUsable` | 必填；布尔值 | 是否能作为武器材料；为 `true` 时至少要有一条可生成的武器类型 |
| `armorUsable` | 必填；布尔值 | 是否能作为防具或饰品材料；为 `true` 时可参与相应装备轴组合 |
| `damageBonus` | 必填；整数 `≥ 0` | 加到武器面板或防具防御基值上的材料加成 |
| `valueFactor` | 可省略，默认 `100`；整数 `> 0` | 价值倍率百分数；`100` 表示基准价值不变 |

材料行还应提供有效的 `category`、`stackLimit`、`marketValue` 等继承字段；不要在材料行填食物属性，除非该材料确实可食用。武器锻造只使用 `weaponUsable=true` 的材料；防具和饰品锻造只使用 `armorUsable=true` 的材料。`damageBonus` 是代码共用的轴字段，虽然用于防具时代表防御增量，字段名仍保持模型现状。

## 修改前检查

1. XML 能解析，所有元素类型、字段名和枚举值都受当前 `DefLoader` 支持；不添加未建模字段。
2. 各表 `defName`、`label` 无重复；`WeaponTypeDef.type` 唯一，数值范围合法。
3. `ArmorSlotDef.defName` 与防具槽位一一对应；每个可用材料至少能组成预期装备，不生成被禁组合。
4. `MaterialDef.defName` 不与 `things.json` 的 `ThingDef.defName` 冲突；物品属性和引用符合[物品表规范](物品表规范.md)。
5. 改动后的基座数量与材料可用标志相符；不要为运行时随机生成的品质、祝福、强化和附魔另建静态装备行。

## 示例

以下武器类型行取自现有的剑定义：

```xml
<WeaponTypeDef>
  <defName>Sword</defName>
  <label>剑</label>
  <description>形制典雅的双刃单手铁剑，挥砍与穿刺兼备，攻守均衡。</description>
  <type>Sword</type>
  <style>OneHand</style>
  <core>Dexterity</core>
  <basePanel>18</basePanel>
  <baseValue>10</baseValue>
</WeaponTypeDef>
```
