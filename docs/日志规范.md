# 日志规范

> 本文档是 Rimisekai 据点日志（领地页签顶部的日志面板、底部「日志」页签的时间线）的**唯一写作与实现标准**。
> 文风沿用 `docs/voice-writing-guide.md`（沉静克制、句式短促、无 emoji），LLM 生成沿用
> `docs/llm-voice-generation-prompt.md` 的提示词骨架。2026-10-07 主人定。

---

## 一、视角：上帝视角，但只写玩家感知得到的

- 日志是旁白，不是系统消息。叙述者站在玩家身后：看得见玩家看得见的，听得见玩家听得见的。
- **感知范围＝玩家所在的房间**（`HubSession.PlayerRoomId`）。别的房间里发生的事、别人心里想的事，
  一律不写。唯一例外沿用旧规：角色在门外找玩家搭话，声音隔着门听得见。
- 不写玩法规则、数值说明、教学提示（AGENTS.md「严禁自造说明文字」照旧）。不写冒号。

## 二、内容类别（`LogKind`）

| 类别 | 何时写 | a 段（系统性信息）出处 | b 段（感受 / 反应）出处 |
|---|---|---|---|
| **场景描述** `Scene` | 玩家来到一处房间（点格前往 `Arrive`、走动 `Move`） | 「你来到了X。」＋房间定义原文 `RoomDef.Description`（`SceneDescription`） | 在场角色对玩家的 Meet 口上（`VoiceTrigger.Meet`，Speech），写成「某某说「……」」 |
| **天气变化** `Weather` | 整点变天、日终换季与当日天气、日终大事件 | 「天气转为雨天。」「季节变为夏季。」等引擎事实 | 暂无出处，留空（见第六节） |
| **当前区域角色在做什么** `Activity` | 时间推进后，与玩家同房的角色的当前行为 | 角色状态地文（`VoiceTrigger.State`，Narration）；无台词系统时为状态机叙述 | 暂无出处，留空 |
| **玩家行动** `Action` | 玩家自己的操作结果（观察、使用设施、交流反馈等） | 各操作原有的叙述文字 | 暂无出处，留空 |

新增类别前先在 `LogKind` 加枚举、在本表补一行，再在 Core 加写入点。

## 三、两段式结构（强制）

每条日志都有两段，**显示为一句话**：

```
a，b
```

- **a＝系统性信息**：客观、可核对的事实——到了哪里、天变成什么、谁在做什么。只用 Core 的定义原文与引擎事实。
- **b＝以玩家为中心的感受，或角色对玩家的反应**：玩家此刻的体感（冷、潮、闻到什么），
  或在场角色冲着玩家的一句话、一个动作。
- 显示规则（唯一实现 `LogEntry.Compose` / `LogEntry.Text`）：a 去掉句末句号，接全角逗号「，」，再接 b。
  **b 为空时只显示 a，a 自带句号**。两段不分行、不分样式，是同一行文字。
- 存储上 a / b 是两个字段（`LogEntry.Fact` / `LogEntry.Feel`），存档存两段（`LogEntryData`），便于以后单独重生成 b。

### 示例（项目口吻）

- 天气：「细雨落在菜垄上，你闻到了泥土的气味。」
- 场景：「你来到了庭院。青石板路的中央立着一口带木篷的水井，璐米埃尔说「大人，请问有什么吩咐吗？」」
- 角色：「赛琳在桌前用羽毛笔计算符文配比，她抬眼看了你一下，又低下头去。」
- 天气（b 为空）：「天气转为雨天。」

写 b 的要点：短（10～18 字）、具体（一个感官细节或一个动作）、不评价、不解释机制；
角色反应遵守该角色的敬称与好感档（见 voice-writing-guide 第三节）。

## 四、两份视图

- **操作快照** `HubSession.Log`：这一次玩家操作写下的条目，按写入先后排（即按时间）；同一角色的活动只留最新一句、
  排在它写下的位置；新操作的首次写入清空旧快照。走路（前往、走动、过界）途中推进的时间不记活动，
  落脚后在场景描述之后按**落脚那间房**写——出发那间房里的人不会出现在「你来到了X」这次日志里。用于操作反馈（底部浅填签）。
- **近期日志** `HubSession.History`：跨操作保留，按写入先后，最旧在前，上限 80 条；
  同一角色的同一句活动不重复入史。领地页签的日志面板与「日志」页签都只读它。

## 五、呈现（竖版）

- 领地页签顶部日志面板（`PortraitLayout.LogPanel`，约 430 高）：最新一条贴底、自下而上排；
  本次操作写下的条目骨白，更早的压暗。字号自 50 往下收到恰好放下最近 4 条，不低于 44；
  收到 44 仍放不下，最旧的整条不画，绝不溢出。整块点一下进「日志」页签。
- 「日志」页签：按游戏日分组，最新在上，每条一枚菱、竖线串起，可拖动滚动。

## 六、b 段的出处与生成指引

- **只用已有的文本基础设施**：Voice/VoiceDirector 挑静态台词、`SceneTextStore`、状态地文/口上包、`GenerationQueue`。
  **挑不出就留空**——禁止在代码里写兜底句（AGENTS.md「禁止硬编码回退文字」）。
- 现有空缺（等内容包或 LLM 补）：天气变化、角色活动、玩家行动这三类的 b 段。
- 将来交给 LLM 生成 b 段时：
  1. 输入＝a 段原文、类别、季节/天气/时刻、玩家所在房间名与描述、同房角色的人设与好感档（沿用 `VoiceGenerationHub` 的上下文拼装）。
  2. 要求：一句，10～18 字，不超过 30 字；以玩家为中心（「你」的体感）或写在场角色对玩家的反应；
     不复述 a 段、不加冒号、不加括号注解、不出现数值与规则；角色台词用「某某说「……」」。
  3. 生成走后台队列（`GenerationQueue`），先落 a 段，b 回来后只填该条的 `Feel`，不另起一条；
     生成失败就保持空，不回退任何固定句。
  4. 内容包里新增的 b 段素材按触发时机挂在角色/世界包上（如天气类可挂世界包 Narration 并以 weather 门控），
     再在 Core 对应写入点取用。
